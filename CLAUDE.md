## О проекте

Арина — ИИ-агент в Telegram, единый цифровой помощник в работе и личных делах.
Автоматически определяет через LLM, к какому контексту (рабочему или личному)
относится каждое сообщение, без ручного переключения режимов пользователем.
Ключевая ценность — не отдельная функция (список дел и напоминания сами по себе не
новы), а долговременная память о пользователе между разговорами.

MVP **сознательно урезан** по итогам критики независимого агента-рецензента:
Telegram-only (без веба), без биллинга (закрытая бесплатная бета), без векторной
(семантической) памяти (структурированная БД + скользящее текстовое summary вместо
неё). Полная история решений и почему они изменились — см. `thoughts/shared/specs/2026-08-19-arina-personal-agent.md`,
раздел «Что изменилось после критики».

## Стек технологий

- **Python** — основной язык
- **python-telegram-bot** v20+ (async) — Telegram-интерфейс
- **openai SDK → OpenRouter** (`base_url` — Cloudflare Worker релей) — доступ к модели
  Claude для классификации сообщений, генерации ответов, документов и summary диалога
- **SQLAlchemy + Alembic + PostgreSQL (psycopg2-binary)** — хранение данных
- **cryptography (Fernet)** — шифрование персональных/рабочих данных пользователя
- **APScheduler** — доставка разовых и повторяющихся напоминаний
- **pydantic-settings** — конфигурация из `.env`
- **pytest** — тесты

## Структура проекта (по плану)

```
config.py                  # конфигурация (pydantic-settings)
db/
  models.py                 # User, Task, Note, DialogSummary
  crypto.py                  # шифрование/расшифровка (Fernet)
  session.py                  # engine/сессия SQLAlchemy
llm/
  client.py                    # клиент OpenRouter (через релей) с retry-логикой
  classify.py                   # классификация сообщений: работа/личное
  documents.py                   # генерация писем/документов по описанию
core/
  tasks.py                        # разбор естественного языка в задачу
  scheduler.py                     # APScheduler, доставка напоминаний
  dialog_summary.py                 # скользящее summary диалога
bot/
  main.py                             # точка входа
  states.py                            # состояния онбординга
  handlers/
    onboarding.py                       # короткий опрос при первом запуске
    free_chat.py                         # приём сообщений, классификация, коррекция
    tasks_flow.py                         # создание/просмотр задач, напоминания
    documents_flow.py                      # генерация документов + подтверждение
tests/
  test_*.py                                # юнит-тесты по модулям
  calibration/                              # калибровочный набор для классификации
```

## Общие правила разработки

- Весь пользовательский текст (сообщения бота, ошибки, подсказки) — **только на русском языке**.
- Конфигурация — только через `config.py` / объект `settings`, не читать `os.environ`
  напрямую в других модулях.
- Персональные/рабочие данные пользователя (задачи, заметки, summary диалога) —
  шифруются перед записью в БД (`db/crypto.py`, Fernet) и никогда не попадают в логи
  в открытом виде (152-ФЗ).
- Каждое сгенерированное письмо/документ — всегда черновик, требующий явного
  подтверждения пользователем перед использованием, никогда не считается готовым к
  отправке автоматически.
- Классификация «работа/личное» — не считать эталонной: у пользователя всегда должен
  быть быстрый способ поправить ошибку классификации.
- В MVP нет платящих пользователей и биллинга — не добавлять оплату/подписку без
  явного решения о переходе к v1.1 (см. спецификацию).
- Каждый новый модуль с логикой — сопровождается тестом в `tests/` в том же PR/коммите.
- Тестовое виртуальное окружение — папка `venv/` в корне проекта (см. `.gitignore`,
  не коммитить).
